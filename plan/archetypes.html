Opportunistic archetype deck-building

Commit to what the run offers: overlay archetypes, continuous commitment, structure by hand, magnitudes by ES. Design constraints from the ledger: hand-applied tier recalibrations regressed; hard gates failed; soft package bonuses succeeded — so everything here is a continuous modulation with defaults that reproduce current behavior.

Commitment scoring

Affinity matrix — fixed structure, NOT ES dims. fn affinity(id, archetype) → tier 0–3 (0 unrelated, 1 filler, 2 core, 3 defining payoff), same for relics. ~120 nonzero entries. Card×archetype as ES dims would add ~450 low-SNR dims to an ES that stalled at 155; the structure is domain knowledge, the magnitudes are what the ES tunes.

raw_a    = Σ_deck tier(card,a) · (1 + 0.5·upgraded) + relic_mult · Σ_relics tier(relic,a)
commit_a = clamp((raw_a − floor_a) / ramp_a, 0, 1)
act_ramp = min(1.0, floor / arch_act_ramp_floor)   // A20-critical: generic Act-1 damage shaping
                                                   // keeps dominating until the deck can specialize

Modulation (added inside DeckPlan::card_adjustment, so rewards, shops, Neow, library grids inherit it):

arch_adj = Σ_a commit_a · act_ramp · onplan_gain_a · tier(card,a) · need_a(card)
         − offplan_pen · act_ramp · max_commit² · offplan(card)
  • need_a: saturation via existing DeckProfile counters — a frost deck at 9 frost sources stops over-paying for a 10th and starts valuing Defragment/energy (dilution control on the bonus side).
  • max_commit²: quadratic off-plan penalty — cheap exploration early, committed decks effectively raise their pick threshold for unrelated filler (the community "A20 decks skip most rewards" behavior). Cards on any live plan (commit > 0.3) are never penalized — hybrids breathe.
  • Never a gate; additive to the ES-tuned table; pick_threshold stays the only decision boundary.
  • Same commit_a feeds shop_relic_value and boss-relic ranks (Frozen Core over Pyramid at high frost commit; Snecko Eye rescued when SneckoBig payoffs owned). Energy-first +40 override stays on top.

Upgrade priorities per archetype

Extend upgrade_score with + Σ_a commit_a · upgrade_gain_a · upgrade_tier(card,a). The defining example: Darkness+ is tier 3 for DarkBurst (auto-triggers growth on all dark orbs) but mediocre globally — exactly what a flat table cannot express. Others: Glacier+/Loop+/Skim+ (Frost), Electrodynamics+ (Lightning), Echo Form+ (PowerEcho), All For One+ (Claw).

// src/htn/archetype.rs (~250 lines)
pub enum Archetype { FrostFocus, LightningAoe, PowerEcho, DarkBurst, ClawZero, SneckoBig }
pub struct Commitments { c: [f32; 6], act_ramp: f32 }
impl Commitments {
    pub fn from_game(game) -> Self;          // one pass, folded into DeckProfile walk
    pub fn pick_adjustment(&self, card) -> i32;
    pub fn upgrade_adjustment(&self, id) -> i32;
    pub fn purge_adjustment(&self, card) -> i32;
    pub fn relic_adjustment(&self, id) -> i32;
}

Params: a fourth flat map archetype: HashMap<String,f32> with keys like frost.onplan; a p.arch(key, default) helper returns code defaults when absent — an empty map reproduces today's baked policy bit-for-bit (safe mid-campaign builds, clean A/B). One prefix-dict entry puts the block into the ES vector.

Expected impact ordering

  1. Off-plan penalty under Frost commitment — converts the mid-game reward stream to community-style A20 skipping (largest behavioral gap vs strong humans).
  2. Commitment-scaled Frost on-plan gains with need-decay (dilution control).
  3. Per-archetype Defend/Strike removal economics.
  4. Archetype-conditional upgrades (Darkness+, Echo Form+).
  5. Conditional Claw/Dark/Snecko opportunism — rare per-run, but exactly the "commit to what the run offers" ask.

Rollout per the ledger's methodology: ship structure with near-neutral defaults, observe on the fixed cohort, let a phase-3+ ES own the magnitudes, accept only on paired fresh cohorts. Magnitudes will legitimately differ between A0 and A20 — that's why they're ES dims.
