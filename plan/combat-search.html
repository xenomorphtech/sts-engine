Combat turn-planning improvements

Fixing the beam search's structural blind spots in src/htn/turnplan.rs. Legend: DET deterministic logic  ES tunable weight for the optimizer.

Diagnosis of current weaknesses

  1. Mid-turn pruning uses wrong block arithmetic. The beam ranks unfinished nodes with unblocked = incoming − block, ignoring Frost-orb passives (2+Focus each, applied before enemy hits), Metallicize, Plated Armor, Orichalcum. Frost-wall lines look "unblocked" and get pruned before an ended final can prove them out. Worst exactly at A20 multi-hit elites.
  2. Beam width wasted on permutations. A-then-B and B-then-A reach identical states and occupy two frontier slots; effective width can collapse from ~13 to ~4 distinct states.
  3. No lethal guarantee. Kill lines can be pruned when intermediate states look bad (damage is heavily down-weighted post-ES: dmg_base ≈ 2.45). Missing exact lethal at A20 = eating one extra boss turn (40+ damage).
  4. Ended states ignore the next turn they can already see. end_turn resolves the whole enemy turn deterministically from cloned RNG — ended nodes are post-enemy-turn states with next intents rolled and visible, but the eval never scores next-turn exposure.
  5. Static target priority. 10 damage into a 12-HP dagger that hits for 25 scores the same as 10 into the boss. No threat/EHP arithmetic.
  6. Why 2-turn lookahead regressed (ledger): (a) comparability violation — nodes at different turn parities shared one frontier with an eval whose semantics flip on turn_advanced; (b) draw decorrelation — branches compared on different realized turn-2 hands, one sample each, no averaging; (c) weights were 1-turn-calibrated. It was a formulation failure, not evidence against lookahead.
  7. Planning cost re-paid per decision: a turn of L plays costs L× a full beam; A20 fights are longest where they're hardest.

Deterministic additions (ranked)

D1 Effective end-of-turn block in the mid-turn eval DET

Replace after.player.block in the !turn_advanced branch of score_state with:

fn end_of_turn_block(g: &Game) -> i32 {
    let frost: i32 = frost_orbs × (2 + focus);
    g.player.block + frost + Metallicize + PlatedArmor
        + (Orichalcum && block == 0 ? 6 : 0)
}

Stops pruning Frost-wall lines and stops stacking Defends on an already-sufficient wall. Highest impact, nearly free.

D2 Frontier deduplication DET

Hash (energy, block, hp, hand, orbs, monster hp/block, powers) after sorting, retain first occurrence before truncate(width). Effectively doubles width for free in big-hand turns.

D3 Exact-lethal DFS with admissible pruning DET

Before the beam: if optimistic_damage(game) ≥ Σ(hp+block) over living monsters, run a DFS over attack plays with a ~20k-step budget (≈7 ms at measured engine speed); return the first proven kill line's first action. The optimistic gate makes it a no-op almost always.

D4 Turn-plan caching DET

Store the best final's action prefix; next decision, if the observed state hash matches the predicted hash, pop the next action without re-searching. Cuts per-turn planning cost ~L-fold; pays for D3 and the rollout below.

D5 Powers-first ordering — not needed

Already emergent from full-turn completion scoring + focus/strength_weight × turns_left. Fix width starvation (D2) instead.

New ES-tunable eval terms (ranked)

E1 Next-turn exposure on ended states ES

The safe half of 2-turn lookahead. On turn_advanced states, the next turn's rolled, real intents are already computed and discarded. Add:

let wall = end_of_turn_block(after);           // retained block + frost + metallicize
let hand_block = cheap_hand_block(after);      // greedy affordable block in the drawn hand
value -= (incoming − wall − hand_block).max(0) × next_exposure_weight × danger_scale;
value -= min(hand_block, (incoming − wall).max(0)) × next_block_tax;  // energy taxed into defense

Biggest single eval win at A20: stops shaving 2 HP off a boss while standing naked in front of a 12×4 multi-attack.

E2 Threat-per-EHP damage concentration ES

focus_mult = 1 + threat_focus_weight × threat / (hp+block) in the dealt loop — rewards finishing low-EHP high-threat enemies even when the kill lands outside the horizon. Static table stays as prior.

E3 Orb-pipeline readiness ES

Slot-fill fraction term plus front-orb ordering: front-Frost bonus scaled by next incoming, front-Lightning/Dark scaled by remaining EHP. Gives Dualcast-vs-channel and evoke sequencing a gradient.

E4 Next-hand quality ES — weight-capped, expect ES to keep near 0 (draw-luck-chasing term that helped sink the 2-turn experiment; include only because testing is free).

E5 Status/curse-injection penalty ES

−status_gain_weight × (statuses in piles − origin). Burns/Dazed/Wounds currently invisible; matters vs Hexaghost, Book of Stabbing, Sentries, Deca, Time Eater.

Multi-turn search: the correct formulation

Key fact: rollouts in this sim are exact, not stochastic — end_turn rolls enemy moves and the next draw from cloned RNG. Expectimax is unnecessary; the 2-turn failure was formulation, not concept.

  1. Terminal-only, fixed-horizon comparison. Per candidate first action: finish turn T with the current beam → take its single best ended final → roll turn T+1 greedily (width ≤ 3) → end it → score only at that common horizon.
  2. Blend, and let the ES decide: score = horizon_blend × score(terminal_T+1) + (1−blend) × score(ended_T) with horizon_blend starting at 0 (exactly today's policy) in the ES vector. If lookahead truly helps at A20, ES pushes it up; if draw noise dominates, it stays 0 at zero cost.
  3. Variance control: exclude hand-dependent terms at the T+1 terminal (compare durable quantities: EHP removed, HP, orbs, powers, retained block); optionally rollout only the top-K≈3 candidates and require a margin to overturn the 1-turn winner.

Cost: ~+20–30% over today (vs 5× for the failed full-beam version); D4 pays for it.

Implementation order

  1. D1 + D2 (few lines; fixes the pruning that gates everything else)
  2. E1 (largest A20 eval gain; reuses D1's helper and the already-computed incoming)
  3. D3 (lethal guarantee)
  4. D4, then blended rollout with horizon_blend handed to ES
  5. E2, E3, E5 as cheap ES-vector extensions; E4 last

All new weights ship with defaults ≈ 0 / current behavior, per the default-preserving pattern; every landing goes through paired fixed-then-fresh cohorts. Re-run the ES on A20 cohorts before judging any A20 claim.
