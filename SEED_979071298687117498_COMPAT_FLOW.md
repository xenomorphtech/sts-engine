## Objective

follow the same decisions and gameplay state transitions as Java

## Lockstep Loop

1. Build the Rust HTN and parity executables.
2. Generate a fresh Rust HTN action log from the seed start.
3. Replay those decisions against a fresh Java session.
4. Run `sts-parity` on the captured Java states and commands.
5. Stop at the first mismatched boundary.
6. Read the corresponding Java source and action ordering.
7. Port only that behavior to Rust and add a focused regression test.
8. Rebuild and repeat from step 2.

## Replay Adaptations That Are Not Engine Fixes

The temporary replay script only translates equivalent command vocabulary:

- map nodes by `(x, y)` and the boss node by its boss label;
- compact Rust IDs and Java display names, such as `BootSequence` and
  `Boot Sequence`;
- equivalent event option labels and Sensory Stone options;
- hidden potion-discard commands accepted by Java's command executor but
  omitted from its published legal-action list.

If Java and Rust require a different number or order of gameplay decisions, do
not hide that in this adapter. Fix the engine boundary.

## Java-Authoritative Fixes Applied So Far

### Act 1 floor 14 map and event

- The row-14 campfire is now reachable. Rust no longer opens the boss choice
  from row 13.
- At Ascension 15+, `NoteForYourself` is excluded from the Exordium event pool.
  With Java's event order and RNG, this seed therefore rolls `WeMeetAgain` on
  floor 14.
- A seed-specific regression test verifies both the row-14 rest node and the
  `WeMeetAgain` event.

### Drug Dealer transform

- Non-Astrolabe event transforms use `miscRng`, not Neow RNG.
- Selected cards are transformed in click order after their source indices are
  removed safely.

### A20 monster fidelity

- Spheric Guardian uses A2 damage 11 and A17 block 35.
- Bronze Orb burns the constructor's base `52..58` HP roll, then rolls the A9
  actual `54..60` HP range.
- Transient starts at 40 damage at A2+ and has Fading 6 at A17+.

### Shop labels

- Java display names with spaces match compact Rust card IDs while preserving
  upgrade matching.

### Awakened One rebirth ordering

- First-form lethal damage enters half-dead Rebirth state.
- A Bronze Scales kill during the monster's attack still lets Java's queued
  `RollMoveAction` consume one `aiRng.random(99)` value.
- Java's later `SetMoveAction(REBIRTH)` restores move 3 after that roll.
- The next Rebirth turn consumes another AI roll and selects Dark Echo. This
  keeps the subsequent second-form move choice aligned.

### Beyond boss reward boundary

- A Beyond boss room does not roll a card reward.
- Its room-complete state retains the unclaimable gold reward but exposes only
  `Proceed`, including the interval between the two A20 bosses.
- Rust no longer inserts an extra `Choose GOLD` HTN decision before the second
  boss.

### Time Eater draw reduction ordering

- The affected draw is queued while Java's `gameHandSize` is still reduced.
- Removing Draw Reduction later in the same boundary restores future hand size
  but does not enlarge that already queued draw.
- Rust snapshots the one-card reduction before its end-of-round power cleanup.


The final corrected boundary was Java's `DrawReductionPower` ordering:

- `onInitialApplication()` decrements `player.gameHandSize` immediately;
- a newly applied stack clears `justApplied` at the first end-of-round hook;
- a later end-of-round reduction removes the power and restores hand size in
  `onRemove()`.

Rust now captures the reduced hand size for the already queued draw before
removing the power. A stacked Draw Reduction power lowers hand size once and
extends duration rather than subtracting its full stack count from every draw.

Both engines now lose at the same point in the second Act 3 boss fight. The
player reaches 0 HP against Time Eater, which has 411/480 HP remaining. The old
"loss with 0 final monsters" state was a consequence of the earlier divergent
simulation and is no longer reproduced by the Java-matched HTN flow.
